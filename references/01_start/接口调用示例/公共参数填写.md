# 公共参数填写

## 老版本的公共参数请参考：[旧版传参方式说明](https://developer.fxiaoke.com/openapi_v2/start/example/old.html)

## 与旧版传参的区别

- token 放在header的authorization中
- x-fs-ea 放在header的x-fs-ea中
- x-fs-userid 放在header的x-fs-userid中
- 员工ID默认不需要转换成FSUID，直接使用CRM中的员工ID
  > 如果要使用FSUID,则在body中添加一个参数，参数名为convertUserId，参数值为true
  ```
  {
   "convertUserId": true
  }
  ```
- 文件上传或文件参数默认使用npath,不在使用mediaId
  > 如果要使用mediaId,则在body中添加一个参数，参数名为convertMediaId，参数值为true
  ```
  {
   "convertMediaId": true
  }
  ```

## 获取 thirdTraceId

所有接口都需要在url后面填入一个**随机字符串**作为thirdTraceId，用于标识你的每一次请求，所以每次请求需携带不同的thirdTraceId。随机字符串请按照 **RFC 4122 标准 UUID Version 4** 来填写。

- 对于非技术人员：可以访问 在线UUID生成器 ，点击 “Generate UUID” 后复制结果。
- 对于技术人员：请使用对应编程语言的 UUID 原生库。

**例子**：

```
https://www.fxiaoke.com/cgi/crm/v2/data/get?thirdTraceId=5ea0422d-98e3-49e0-a3cb-9bd5517d1f30
```

## 设置请求头

每次接口请求前（获取 token 的请求除外），**都需要**在 Headers 设置请求头

![示例](https://a9.fspage.com/FSR/docs/openapi/open-api/guide/api/public-1.png)

### 必填参数说明

#### authorization

**参数类型** ：String

**获取途径** ：固定值 “Bearer ”，后面加上 [token](https://developer.fxiaoke.com/openapi_v2/start/auth/auth-code.html)

**注意** ：Bearer后面有一个空格

**取值示例** ：Bearer 1247D6096162AB2FDCEA46D6D7B74B33

#### x-fs-ea

**参数类型** ：String

**获取途径** ：查看 [客户端凭证模式](https://developer.fxiaoke.com/openapi_v2/start/auth/app-info.html)，从返回结果中获取 “ea”

**取值示例** ：12345

#### x-fs-userid

**参数类型** ：String

**获取途径** ：

![userid](https://a9.fspage.com/FSR/docs/openapi/open-api/guide/api/public-2.png)

1. 点击 “CRM” 应用
2. 搜索 “人员”
3. 点击需要查询人员的 “系统名”
4. 在账号信息中找到 “员工ID”，即为x-fs-userid

### 平台公共参数

***参数位于json最外层***

```json
{
  "convertUserId": false,
  "convertMediaId": false,
  "data": {

  }
}
```

| 参数 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| convertUserId | boolean | 否 | 是否转换用户ID，默认为 `true` ，新版参时默认为 `false` |
| convertMediaId | boolean | 否 | 是否否转换媒体ID，默认为 `true`，新版参时默认为 `false` |
